CiteDesk · RAG customer support

A support chatbot that shows its sources and knows when to call a human.

It answers customers from a business's own documents (PDFs, Word files, web pages, spreadsheets), cites the passage behind every claim, replies in the customer's language, and hands the conversation to a person through n8n when the documents don't cover a question.

Source code on GitHub

Everything on this page comes from a real run on 27 Sep 2026: deepseek-flash for answers, bge-m3 for search, on the knowledge base of Loopline E-Bikes, a fictional shop. The chat replays those recorded answers; to ask your own questions, run it locally (one command).

Measured, not eyeballed

37 test questions in English, French and Chinese: questions the documents answer, questions only a person can handle (an order lookup, a discount, a complaint), off-topic requests and small talk. Each answer is graded automatically.

Why search is hybrid

The documents are in English. Keyword search (BM25) can't match a French or Chinese question to an English page; multilingual embeddings can. BM25 stays in the mix because it is exact where embeddings blur: error codes like E07, prices, product names. CiteDesk fuses both rankings.

How it works

A small, readable Python codebase: no LangChain, no vector database, no framework magic. Each guard-rail is plain code with a test.

IngestPDF, Word, Markdown, HTML, CSV and URLs are split by heading into passages. Re-indexing only re-embeds what changed.
RetrieveBM25 and multilingual embeddings rank passages; reciprocal rank fusion merges the two lists.
GateIf nothing is similar enough, the model gets no sources and the question goes to a person instead of being improvised.
AnswerAny OpenAI-compatible model writes a short answer as JSON, citing sources by number, in the customer's language.
VerifyCitations must point at real sources; an uncited "answer" isn't trusted. Handoffs go to n8n → Telegram, Slack or e-mail.

For the business

  • One <script> tag adds the chat widget to any website.
  • When the bot can't help, the customer leaves an e-mail and the team gets the question, the reason and what the bot said.
  • A nightly n8n workflow re-reads the documents, so updated prices reach the bot by themselves.
  • Runs on a hosted model, or fully locally with Ollama when documents can't leave the building.

For the developer

  • FastAPI service with /ask, /contact, /reindex, rate limiting and a JSONL conversation log.
  • citedesk eval grades retrieval and answers on a JSONL question set, so prompt or model changes are measured.
  • Three n8n workflows (handoff alerts, nightly re-index, Telegram bot) with unit-tested Code nodes.
  • 120+ tests and CI on every push.

What the team sees

When the bot hands over, n8n posts the question, the reason and the bot's reply to the team's Telegram (or Slack, or e-mail). If the customer leaves an e-mail address, that arrives too. These two alerts came from the order-status question above, in an end-to-end run with n8n 2.35.
